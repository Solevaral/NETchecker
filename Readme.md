<h1 align="center">Netchecker</h1>

<p align="center">Диагностика интернет-соединения по уровням модели OSI — с наглядной схемой сети.</p>

---

Программа отвечает на вопрос «почему не работает интернет». Она показывает цепочку от вашего
компьютера до сайта, отмечает участок, где теряется связь, и объясняет причину дважды: простыми
словами и на языке сетевика.

```
[Ваш компьютер] ── [Роутер] ──✕── [Провайдер] ── [Фильтрация] ── [Интернет] ── [Сайт]
                                ⚡ обрыв здесь
```

Один самодостаточный исполняемый файл: ни рантайма, ни установщика, ни интернета для запуска —
что важно, потому что нужна программа ровно тогда, когда интернета нет.

## Что уже работает

- Схема сети с адресами узлов и отметкой места обрыва.
- Проверки L1–L2: сетевые адаптеры, линк, IP-адрес, распознавание APIPA, шлюз.
- **Точный ICMP**: `IcmpSendEcho` на Windows — работает без прав администратора,
  ICMP-сокеты на Unix. Задержки, потери и разброс по четырём пробам.
- **Трассировка маршрута** с разбором участков: ваша сеть, ещё один роутер в цепочке,
  CGNAT, провайдер. Второй роутер в квартире больше не выдаётся за провайдера.
- **Обнаружение обходов**: zapret/winws, GoodbyeDPI, VPN-туннели, Hiddify, Xray, tg-ws-proxy
  и другие локальные прокси — по процессам, туннельным интерфейсам и слушающим портам.
  Если трафик идёт через туннель, программа говорит об этом первым делом.
- **Разбор блокировок**: подмена DNS (сравнение системного резолвера с эталоном по HTTPS),
  перехват провайдером запросов к чужим DNS-серверам, фильтрация по имени сайта.
  Программа отличает «сайт лежит» от «сайт блокируют», потому что проверяет это сравнением,
  а не списками адресов.
- **Признаки транзитного фильтра (ТСПУ)**: обрыв приходит быстрее, чем физически мог бы
  ответить сам сервер; одинаковое поведение у несвязанных сайтов; разница между целым
  и разделённым первым пакетом.
- **Страницы-заглушки**: если вместо сайта подставили страницу «доступ ограничен»,
  программа это распознаёт — по формулировкам заглушки и по перенаправлению на чужой домен,
  а не по списку провайдеров, который устарел бы за месяц.
- **Подмена сертификата**: сертификат сервера читается из рукопожатия и сверяется
  с запрошенным именем. Если соединение вскрывают, предъявленный сертификат выписан
  не на тот сайт — это и ищется.
- **Замедление скорости**: замер к нескольким точкам и сравнение между ними. Односторонняя
  просадка при сопоставимой задержке — признак избирательного ограничения; если же дальняя
  точка просто дальше, программа честно говорит, что вывода по таким данным не сделать.
- Проверки L3–L4: отклик роутера, доступность опорных узлов, поиск запретов на пути.
- Проверка L7: разрешение имён и соединение с сайтом.
- Понятный вердикт с конкретными шагами и переключатель «простой / экспертный режим».
- **Свой список целей**: домены и адреса правятся прямо в окне, построчно — список удобно
  вставлять целиком. Ссылки приводятся к имени сами (`https://site.ru/path?x=1` → `site.ru`),
  повторы схлопываются, непонятые строки возвращаются пользователю, а не пропадают.
  Рядом таблица с результатом по каждой цели и поиск по ней. Список сохраняется между
  запусками.
- **Список по умолчанию** смешанный: заведомо рабочие в России ресурсы вперемешку с теми,
  с которыми обычно бывают сложности. Без эталонов список бесполезен — «не открывается»
  не с чем сравнить, и блокировку не отличить от обрыва связи.
- **Наблюдение за связью**: программа опрашивает канал в фоне, рисует график задержек
  и ведёт журнал обрывов — «когда пропадало и надолго ли». Именно так ловятся плавающие
  проблемы, которых в момент разовой проверки не видно.
- **Значок рядом с часами**: закрытие окна прячет программу туда, а не завершает её —
  наблюдение продолжает работать. Цвет значка показывает состояние связи (серый — наблюдение
  выключено, зелёный, жёлтый, красный), рядом всегда есть подсказка текстом.
  В меню: открыть, проверить сейчас, тумблер наблюдения, автозапуск, выход.
- **Автозапуск с системой** — программа поднимается свёрнутой и сразу наблюдает за связью.
  Она нужна ровно тогда, когда связь пропала, а в этот момент её никто не запускает.
- Вкладка «Отчёт»: полный текст с кнопками «Скопировать» и «Сохранить в файл» —
  чтобы отправить в поддержку провайдера. То же самое без окна: `netchecker --report`.

Отдельно про честность выводов: если на компьютере работает средство обхода DPI, программа
не говорит «блокировок нет». Обход для того и запущен, чтобы фильтр не сработал, поэтому
отрицательный вывод при нём недостоверен — и программа прямо это пишет.

## Что будет дальше

- Системные уведомления при обрыве: сейчас программа сообщает о нём цветом значка
  и подсказкой, но всплывающего окна не показывает.
- Мониторинг в фоне, графики задержек и журнал обрывов.
- Значок в трее, меняющий цвет по состоянию связи, сворачивание в трей и автозапуск.

## Сборка

Нужен только [Rust](https://rustup.rs). Никаких системных библиотек на Windows.

```bash
cargo build --release
```

На Linux для сборки GUI понадобятся заголовки X11/Wayland из репозитория дистрибутива.

### Где оказывается готовая программа

Cargo не спрашивает, куда класть результат, и никуда его не устанавливает — файл появляется
внутри проекта, в папке `target`:

| Команда | Путь к файлу | Размер | Зачем |
|---|---|---|---|
| `cargo build --release` | `target/release/netchecker.exe` | ~8 МБ | рабочая сборка |
| `cargo build` | `target/debug/netchecker.exe` | ~46 МБ | отладочная: тяжелее и открывает окно консоли с логами |

На Linux то же самое, только без расширения: `target/release/netchecker`.

Релизный файл самодостаточный — скопируйте его куда угодно и запускайте, ничего рядом лежать
не должно. Папка `target` намеренно не попадает в репозиторий: она пересобирается из исходников
и весит сотни мегабайт.

Если не хочется искать файл руками:

```bash
cargo run --release
```

Эта команда соберёт программу и сразу её запустит.

## Как устроено

Диагностика полностью отделена от интерфейса: проверки идут в фоновом потоке и присылают
события в окно через канал, поэтому интерфейс не замирает на сетевых тайм-аутах.

| Файл | Назначение |
|---|---|
| `src/model.rs` | уровни OSI, статусы, результаты проверок, узлы схемы, вердикт |
| `src/bus.rs` | канал событий между движком и окном |
| `src/privileged.rs` | определение доступного ICMP-транспорта и прав |
| `src/engine/icmp.rs` | эхо-запросы с управлением TTL, свой транспорт под каждую ОС |
| `src/engine/trace.rs` | трассировка и отнесение узлов к участкам сети |
| `src/engine/bypass.rs` | поиск VPN, прокси и средств обхода блокировок |
| `src/engine/dns.rs` | свои DNS-пакеты, запросы по UDP и по HTTPS |
| `src/engine/tls.rs` | ClientHello вручную, пробы по имени сайта |
| `src/engine/cert.rs` | разбор сертификата в DER и сверка имён |
| `src/engine/http.rs` | запрос по HTTP и распознавание страниц-заглушек |
| `src/engine/speed.rs` | замер скорости и поиск избирательного замедления |
| `src/engine/censorship.rs` | сведение проб в вердикт: блокировка, подмена или сайт лежит |
| `src/engine/` | остальные проверки, по файлу на группу уровней |
| `src/targets.rs` | список целей: разбор построчного ввода |
| `src/settings.rs` | настройки и их хранение |
| `src/monitor.rs` | фоновое наблюдение: замеры, оценка состояния, журнал обрывов |
| `src/tray.rs` | значок рядом с часами и автозапуск |
| `src/report.rs` | текстовый отчёт |
| `src/ui/` | окно, схема сети, оформление |
| `src/logo.rs` | логотип, нарисованный кодом: любой размер и цвет без файлов |
