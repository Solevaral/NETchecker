<h1 align="center">Netchecker</h1>

<p align="center">Диагностика интернет-соединения по уровням модели OSI — с наглядной схемой сети.</p>

---

Программа отвечает на вопрос «почему не работает интернет». Она показывает цепочку от вашего
компьютера до сайта, отмечает участок, где теряется связь, и объясняет причину дважды: простыми
словами и на языке сетевика.

```
[Ваш компьютер] ── [Роутер] ──✕── [Провайдер] ── [Фильтрация] ── [Интернет] ── [Сайт]
                                ⚡ обрыв здесь
```

Один самодостаточный исполняемый файл: ни рантайма, ни установщика, ни интернета для запуска —
что важно, потому что нужна программа ровно тогда, когда интернета нет.

## Что уже работает

- Схема сети с адресами узлов и отметкой места обрыва.
- Проверки L1–L2: сетевые адаптеры, линк, IP-адрес, распознавание APIPA, шлюз, активный VPN.
- Проверки L3–L4: отклик роутера, доступность опорных узлов интернета.
- Проверка L7: разрешение имён и соединение с сайтом.
- Понятный вердикт с конкретными шагами и переключатель «простой / экспертный режим».
- Работа без прав администратора; с правами включаются более точные замеры.

## Что будет дальше

- Точный ICMP и трассировка: `IcmpSendEcho2` на Windows без прав, raw-сокеты с правами.
- Разбор блокировок: подмена DNS, RST по SNI, страницы-заглушки, блокировка по IP, замедление.
- Определение ТСПУ по месту и манере обрыва, а не по содержимому.
- Обнаружение обходных средств: zapret, VPN, tg-ws-proxy — и честное предупреждение,
  что результаты сняты «через обход».
- Свой список целей: домены и IP построчно, таблица с поиском.
- Мониторинг в фоне, графики задержек и журнал обрывов.
- Значок в трее, меняющий цвет по состоянию связи, сворачивание в трей и автозапуск.

## Сборка

Нужен только [Rust](https://rustup.rs). Никаких системных библиотек на Windows.

```bash
cargo build --release
```

На Linux для сборки GUI понадобятся заголовки X11/Wayland из репозитория дистрибутива.

### Где оказывается готовая программа

Cargo не спрашивает, куда класть результат, и никуда его не устанавливает — файл появляется
внутри проекта, в папке `target`:

| Команда | Путь к файлу | Размер | Зачем |
|---|---|---|---|
| `cargo build --release` | `target/release/netchecker.exe` | ~8 МБ | рабочая сборка |
| `cargo build` | `target/debug/netchecker.exe` | ~46 МБ | отладочная: тяжелее и открывает окно консоли с логами |

На Linux то же самое, только без расширения: `target/release/netchecker`.

Релизный файл самодостаточный — скопируйте его куда угодно и запускайте, ничего рядом лежать
не должно. Папка `target` намеренно не попадает в репозиторий: она пересобирается из исходников
и весит сотни мегабайт.

Если не хочется искать файл руками:

```bash
cargo run --release
```

Эта команда соберёт программу и сразу её запустит.

## Как устроено

Диагностика полностью отделена от интерфейса: проверки идут в фоновом потоке и присылают
события в окно через канал, поэтому интерфейс не замирает на сетевых тайм-аутах.

| Файл | Назначение |
|---|---|
| `src/model.rs` | уровни OSI, статусы, результаты проверок, узлы схемы, вердикт |
| `src/bus.rs` | канал событий между движком и окном |
| `src/privileged.rs` | определение доступного ICMP-транспорта и прав |
| `src/engine/` | сами проверки, по файлу на группу уровней |
| `src/ui/` | окно, схема сети, оформление |
| `src/logo.rs` | логотип, нарисованный кодом: любой размер и цвет без файлов |
